# 模型语义标签（dsh-private-model-routing）

在 **设置 → 模型** 的每个 provider 卡片里加一个「语义标签」编辑器：给任意模型写你自己的标签——低成本 / 代码特化 / 快速 / 多模态 / 不计费……——Agent 会把这些标签当作路由依据，在委派子代理时按标签挑模型。

## 它做什么

- **图形化编辑，不用改配置文件**：设置 → 模型 → 展开任意 provider 卡片（含「添加模型提供方」的草稿卡片），下方就是标签编辑器：
  - 模型 ID 手动填写（例如 `qwen3-32b`）；
  - 标签用逗号分隔（支持中文逗号、分号、顿号），例如 `低成本、代码特化`；
  - 添加/删除标签即时保存到 profile 的设置文档（`private-model-routing` 命名空间），没有「保存」按钮。
- **把语义送进模型提示**：Host 每次组装系统提示时读取标签，渲染成一段 `## Model semantics`，列出每个被标记的路由和标签。
- **和子代理选择策略联动**：如果某个被标记的路由同时出现在「插件 → 子代理 → 模型选择」的允许列表里，该行会标上 `(delegable)`；Agent 会优先把高重复、低难度的工作委派过去，并把判断类工作留在当前模型。
- **未打标签时的默认语义**：被允许给子代理、但没有标签的路由，仍按上一版行为描述为「私有部署、不按 token 计费」。

## 怎么用

1. **打开编辑器**：设置 → 模型 → 找到你的 provider 卡片（例如自定义的 vLLM 网关），底部即是「语义标签」区。
2. **加标签**：模型 ID 填 `qwen3-32b`，标签填 `低成本、代码特化、快速`，点「添加」。
3. **（可选）允许委派**：插件 → 子代理 → 模型选择 → 打开开关并勾选同一条 `provider/model`。只有勾选过的路由才能被 `subagent` 显式选中。
4. **开新会话**：提示词与子代理策略都在新会话组装时生效；当前已存在的会话不会变。

## 存储与范围

- 标签存在本插件的设置命名空间 `private-model-routing` 的 `tags` 字段（volatile，写入即生效，不需要重载插件）。它是普通设置数据，跟随 profile 的 `cordis.patch.yml` 持久化，也可以手写：

```yaml
- id: private-model-routing
  name: '@local/dsh-private-model-routing'
  config:
    tags:
      - provider: vllm-local
        model: qwen3-32b
        labels: [低成本, 代码特化]
```

- 每个卡片只编辑**本 provider** 的标签；写入是整表替换并按 revision 校验，遇到并发冲突会提示重试。
- 支持 `llm-pi-ai` 与 `llm-deepseek` 两个 adapter 家族的 provider 卡片（账号卡片没有编辑器）。
- 标签本身不授予委派权限——委派白名单仍归官方「子代理 → 模型选择」设置。

## 验证

- 设置 → 模型 中应出现「语义标签」区，添加标签后再打开卡片仍在。
- 新会话里问 Agent「你能用哪些子代理模型」，它应能通过 `list_subagent_models` 列出允许的路由，并在系统提示里看到标签。
